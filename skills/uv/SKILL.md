# uv

`uv` is the default workflow for Python package, environment, and project management.

## When to use this skill

Use this skill whenever a task includes Python dependency management, environment setup, scripts, or package tooling.

Prefer `uv` especially when you see:

- `uv.lock`
- `pyproject.toml` with uv-managed workflows
- `requirements*.txt` files generated by uv

Do not force uv in projects already managed by another tool:

- `poetry.lock` (Poetry)
- `pdm.lock` (PDM)

## Core rules

- Use `uv` commands instead of raw `pip` in uv-managed projects.
- Use `uv run ...` instead of calling `python` directly.
- Avoid manual virtualenv activation when `uv run` can handle execution.
- Prefer project-local dependency management and lockfile-driven installs.

## Workflow selection

### Scripts

Use for standalone Python files.

```bash
uv run script.py
uv run --with requests script.py
uv add --script script.py requests
```

### Projects

Use when working in a `pyproject.toml` project or any repo with `uv.lock`.

```bash
uv init
uv add requests
uv remove requests
uv sync
uv sync --locked --all-extras
uv run <command>
uv run python -c "print('ok')"
uv run --python 3.12 <command>
uv run -- flask run -p 3000
```

### Tools

Use for one-off CLI tools without permanent installation.

```bash
uvx ruff check .
uvx ty check
uvx ruff@0.8.0 check .
```

Use `uvx` only for trusted tools and package names.

### Pip interface (legacy workflows)

Use only when a repository is explicitly requirements-based and does not use a uv project lockfile.

```bash
uv venv
uv pip install -r requirements.txt
uv pip install -r pyproject.toml --all-extras
uv pip install --group dev
uv pip compile requirements.in -o requirements.txt
uv pip sync requirements.txt
uv pip compile --universal requirements.in -o requirements.txt
uv pip list --outdated
```

### CI and containers

Use these patterns when installing into reproducible build environments.

```bash
uv sync --locked --all-extras
uv pip install --system -r requirements.txt
```

## Migration mappings

### pyenv to uv

```bash
pyenv install 3.12      -> uv python install 3.12
pyenv versions          -> uv python list --only-installed
pyenv local 3.12        -> uv python pin 3.12
pyenv global 3.12       -> uv python install 3.12 --default
```

### pipx to uv

```bash
pipx run ruff           -> uvx ruff
pipx install ruff       -> uv tool install ruff
pipx upgrade ruff       -> uv tool upgrade ruff
pipx list               -> uv tool list
```

### pip and pip-tools to uv pip

```bash
pip install package     -> uv pip install package
pip install -r req.txt  -> uv pip install -r req.txt
pip freeze              -> uv pip freeze
pip-compile req.in      -> uv pip compile req.in
pip-sync req.txt        -> uv pip sync req.txt
```

## Additional execution patterns

```bash
echo 'print("hello")' | uv run -
uv run --with rich script.py
uv run --no-project script.py
```

## Anti-patterns

Do not do this in uv-managed projects:

```bash
pip install requests
python script.py
python -m venv .venv && source .venv/bin/activate
```

Use this instead:

```bash
uv add requests
uv run script.py
uv run <command>
```

## Safety and consistency

- Pin or lock dependencies in project workflows.
- Keep dependency updates scoped to the user request.
- Prefer minimal, reversible environment changes.
- If there is an existing toolchain, follow the repository's conventions before introducing uv.
